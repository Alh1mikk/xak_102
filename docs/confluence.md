# Вне афиши — техническая документация

«Вне афиши» собирает культурные события Башкортостана. Веб-интерфейс показывает каталог, ИИ-подборки и пешие маршруты. Бот Telegram использует тот же каталог и отправляет персональные подборки.

## Развёртывание

Требуются Docker Engine и Docker Compose v2. Первый запуск скачивает образы и веса модели. В проверенной локальной установке веса Qwen2.5 7B занимают около 4,7 ГБ.

```bash
git clone https://github.com/Alh1mikk/xak_102.git
cd xak_102
cp .env.example .env
docker compose up --build -d
docker compose ps -a
docker compose logs --tail=50 api importer ollama-model
```

Сайт доступен на http://127.0.0.1:8080, Swagger на http://127.0.0.1:8000/docs. Браузер обращается к API через префикс `/api` на порту сайта. Успешный выход контейнера `ollama-model` с кодом 0 означает, что загрузка модели завершена. Первый импорт может закончиться уже после запуска сайта.

| Настройка | Назначение |
| --- | --- |
| `WEB_BIND`, `WEB_PORT` | Адрес и порт Nginx. По умолчанию `127.0.0.1:8080`. |
| `BACKEND_IMAGE`, `WEB_IMAGE` | Переопределение образов для доставки из GHCR. |
| `OLLAMA_URL`, `OLLAMA_MODEL` | Адрес Ollama и тег модели. По умолчанию `http://ollama:11434` и `qwen2.5:7b`. |
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_BOT_USERNAME` | Токен из BotFather и необязательное имя для ссылки привязки. Без имени API пробует получить его через `getMe`. Старый маршрут входа через Telegram требует оба значения. |
| `SMTP_HOST`, `SMTP_FROM`, `EMAIL_CODE_SECRET` | Обязательные значения для входа по почте. Секрет генерируется командой `openssl rand -hex 32`. |
| `SMTP_PORT`, `SMTP_IMPLICIT_TLS` | По умолчанию STARTTLS на 587. Для TLS с начала соединения задайте `SMTP_IMPLICIT_TLS=true`, порт по умолчанию 465. |
| `SMTP_USERNAME`, `SMTP_PASSWORD` | Учётные данные SMTP. Для Gmail и Яндекс Почты укажите почтовый адрес и пароль приложения. |
| `AUTH_SECURE_COOKIE` | Установите `true` для HTTPS, оставьте `false` для локального HTTP. |
| `SOURCE_ADMIN_TOKEN` | Секрет для административного API источников. |
| `PUBLIC_WEB_URL` | Прежняя настройка ссылок входа. Текущий вход по коду её не читает. |

PostgreSQL и Ollama хранят данные в томах `postgres_data` и `ollama_models`. Для остановки используйте `docker compose down`. Ключ `-v` удаляет тома. API при запуске создаёт отсутствующие таблицы через SQLAlchemy и пересчитывает проверку географии. Для изменения существующих колонок требуется отдельная миграция. Перед обновлением с изменением схемы сохраните резервную копию PostgreSQL.

Для локального почтового теста используйте `docker compose -f compose.yaml -f compose.mail-test.yaml up --build -d`. Mailpit открывается на http://127.0.0.1:8025 и принимает письма внутри Docker. Для реальной доставки запустите основной Compose со своим SMTP. Публичный сайт размещайте за HTTPS-прокси и храните реальные секреты только в окружении сервера.

## Поток данных и модели

Nginx отдаёт React-приложение и проксирует запросы в FastAPI. Импортёр получает JSON «Бюро Культуры» при старте и после успешного запуска ждёт 24 часа. После ошибки интервал повтора пять минут. События обновляются по ID источника. Для объединения записей между источниками учитываются название, время, город и адрес. Сверка координат с полигоном Башкортостана оставляет в публичной выдаче только географически проверенные карточки. Отменённые и черновые события скрываются. Координаты и URL поступают из данных источника.

| Модель данных | Роль |
| --- | --- |
| `City`, `Category` | Справочники городов и категорий |
| `Event` | Карточка, время, статус, адрес, возраст, цена, постер, организатор |
| `Source`, `EventSource` | Источник, внешний ID, исходный JSON, URL и дата последнего получения |
| `ImportLog` | Схема для результатов импорта |
| `verified_regional_sources` | Внутренний реестр записей с подтверждённой географией |
| `EmailUser`, `TelegramUser` | Учётные записи, хеши сессий, время истечения |
| `Preferences` | Фильтры подборки, подписка, связь с Telegram и отметка последней отправки |

Основная LLM — `qwen2.5:7b`. В локальном хранилище также есть `qwen2.5:3b` (около 1,9 ГБ), прежний вариант, который можно указать в `OLLAMA_MODEL`. Свободный запрос разбирается правилами и моделью. База отбирает события по фильтрам, затем Ollama ранжирует кандидатов по карточкам. При отказе модели доступны детерминированные фильтры и хронологическая выдача. Быстрые шаблоны `family`, `friends`, `free` задают диапазон и ограничения явно. Семейный шаблон при пустых выходных ищет ближайшие варианты на две недели. Шаблон бесплатных событий проверяет 14 календарных дней. Город распознаётся из текста по справочнику. Семейный поиск проверяет пометки об аудитории источника.

Карта использует Leaflet и OpenStreetMap. Встроенный пеший маршрут рассчитывает FOSSGIS / OSRM. Для открытия маршрута во внешнем сервисе передаются координаты остановок в порядке начала событий. Длинные маршруты Google Maps делятся на участки. Время просмотра событий в длительность прогулки не включено.

## REST API

Все пути ниже указаны для прямого доступа к FastAPI. Через веб-сервис добавьте `/api`. JSON-схема доступна по `/openapi.json`, Swagger по `/docs`, ReDoc по `/redoc`. Даты в ответах имеют формат ISO 8601. Для дат без смещения в фильтрах каталога применяется время Башкортостана (UTC+5). Ошибки FastAPI возвращаются с полем `detail`, ошибки валидации имеют статус 422.

| Метод и путь | Параметры и результат |
| --- | --- |
| `GET /` | Возвращает `status` и имя сервиса. |
| `GET /health` | Проверяет подключение к PostgreSQL и возвращает `{"status":"ok"}`. |
| `GET /events/` | Публичный список `EventOut`. Параметры `city_id`, `category_id` (UUID), `date_from`, `date_to`, `price_max`, `age_max`, `q` (поиск по заголовку), `limit` (1–200, по умолчанию 50), `offset` (от 0). Границы дат включаются. Для только будущих событий передайте `date_from`. |
| `GET /events/cities` | Массив `{id,name,district}`. |
| `GET /events/categories` | Массив `{id,name,slug}`. |
| `POST /sources/` | JSON `{name,base_url}`, заголовок `X-Admin-Token`. Возвращает `{id,name}`, без корректного токена — 403. |
| `POST /ai/search` | JSON `{text,previous_text?,preset?}`. `text` 1–500 символов, `previous_text` до 500. `preset` принимает `family`, `friends`, `free`. Ответ содержит `query`, `filters_applied`, `explanation`, `events`, `model_used`, `model_ranked`. |
| `GET /auth/config` | `{email_enabled}` сообщает, заполнена ли конфигурация почты. |
| `POST /auth/email/request` | JSON `{email}`. Отправляет шестизначный код, возвращает `{ok:true}`. Ошибки 422 (адрес), 429 (повторный запрос), 503 (SMTP или настройки). |
| `POST /auth/email/confirm` | JSON `{email,code}`, код строкой из шести цифр. Возвращает `{name}` и cookie. Ошибки 401 (код), 429 (лимит попыток), 503 (конфигурация). |
| `POST /auth/telegram` | Старый маршрут входа. Принимает подписанные данные Telegram с `id`, `auth_date`, `hash` и полями профиля. Возвращает `{name}` и cookie. Ошибки 401 и 503. Веб-интерфейс использует почту. |
| `GET /auth/me` | По cookie возвращает `{name}` или JSON `null`. |
| `POST /auth/logout` | Отзывает серверную сессию, удаляет cookie, возвращает `{ok:true}`. |
| `GET /preferences` | Требует сессию email. Возвращает сохранённые фильтры, `weekly` и `linked`. |
| `PUT /preferences` | Требует сессию email. JSON `{city_id?,category_id?,price_max?,family_only?,weekly?}`. Цена от 0 до 1 000 000. Возвращает `{ok:true}`. |
| `POST /preferences/telegram` | Требует сессию email. Возвращает `{url}` с одноразовой ссылкой на 10 минут. Ошибка 503 при недоступной конфигурации бота. |
| `DELETE /preferences/telegram` | Требует сессию email. Отвязывает чат и отключает подписку. Возвращает `{ok:true}`. |

Маршруты предпочтений возвращают 401 без подходящей сессии. Код email действует 15 минут, хранится как HMAC и расходуется при входе. Повторный запрос на тот же адрес ограничен одной минутой. После пяти неверных попыток нужно запросить новый код. Cookie `afisha_session` живёт семь дней, имеет `HttpOnly`, `SameSite=Lax` и опциональный `Secure`. Для каждой учётной записи хранится одна активная сессия.

`EventOut` включает `id`, `title`, `description`, `address`, `start_at`, `end_at`, `price_min`, `price_max`, `age_limit`, `image_url`, `organizer`, `status`, `latitude`, `longitude`, `source_urls`, вложенные `city` и `category`. Отсутствующие значения допускают `null`. Фильтр `price_max` сравнивает предел с минимальной ценой билета. События с неизвестной ценой при этом исключаются.

```bash
curl -fsS 'http://127.0.0.1:8000/events/?limit=5&price_max=1000'
curl -fsS 'http://127.0.0.1:8000/ai/search' \
  -H 'Content-Type: application/json' \
  -d '{"text":"Куда сходить с детьми на выходных?","preset":"family"}'
```

## Telegram и внешние API

Запуск бота: `docker compose --profile telegram up --build -d`. Бот использует Telegram Bot API для long polling (`getUpdates`), регистрации меню (`setMyCommands`) и отправки (`sendWidget`, `sendMessage`). Команды `/start`, `/help`, `/random`, `/family`, `/weekend`. Свободный текст вызывает ИИ-поиск. Привязка через `/start <код>` доступна в личном чате. Если Telegram отклоняет HTML-виджет, бот отправляет текст. На текущем боте обычная отправка подтверждена Telegram, а тестовый виджет получил `INPUT_MEDIA_WIDGET_NOT_ALLOWED`.

Бот проверяет еженедельные подписки каждые пять минут. Отправка выполняется по четвергам после 18:00 по времени Башкортостана, до пяти подходящих событий на следующую неделю. Без подходящих карточек рассылка пропускается. Внешние интеграции также включают Ollama `/api/chat`, SMTP, API «Бюро Культуры», тайлы OpenStreetMap и пешеходный API FOSSGIS.

## Тесты, CI и диагностика

```bash
docker compose -f compose.test.yaml -p afisha-test up --build --abort-on-container-exit --exit-code-from integration
docker compose -f compose.test.yaml -p afisha-test down -v
```

Docker запускает Python unittest и Node test при сборке. Интеграционный Compose проверяет запросы через Nginx и API с отдельной PostgreSQL. GitHub Actions запускает тесты на PR и push в main. После успешной проверки main публикуются образы backend и frontend в GHCR с SHA коммита. Автодеплой запускается при `AFISHA_DEPLOY=true` на Linux runner с меткой `afisha` и использует `AFISHA_ENV_FILE` как путь к серверному файлу окружения.

| Симптом | Проверка |
| --- | --- |
| Сайт не поднимается | `docker compose ps -a`, затем логи `db`, `ollama-model` и `api`. |
| Каталог пуст | Логи `importer`, доступность источника, география и даты карточек. |
| ИИ-подборка медленная | Логи `ollama` и `api`, `docker compose exec ollama ollama list`. |
| Код не приходит | `GET /auth/config`, настройки SMTP, пароль приложения и логи `api`. В тестовом режиме откройте Mailpit. |
| Бот не отвечает | Проверьте профиль Compose, токен в локальном окружении и логи `bot`. |

## Первые 30 минут в проекте

1. Запустите Compose по инструкции выше. Для первого прохода используйте Mailpit и оставьте токен Telegram пустым. Это позволяет пройти каталог, поиск, почтовый вход и профиль без внешних учётных данных.
2. Откройте сайт и дождитесь первой выборки. Нажмите «Подобрать событие», попробуйте «С друзьями» или задайте свой вопрос. Карточки могут различаться в зависимости от дат и текущего импорта. При пустой выдаче проверьте каталог без ограничения цены и даты.
3. Выберите две карточки с разными площадками и нажмите «Построить пеший маршрут». Проверьте карту и ссылки на внешние карты. Для почтового входа запросите код, откройте Mailpit, введите код и перезагрузите страницу.
4. Откройте Swagger и сравните вызов `POST /ai/search` с результатом на сайте. В DevTools на вкладке Network видно, что браузер использует `/api/ai/search`.
5. Перед первым изменением запустите интеграционный Compose. Для правок интерфейса выполните `cd frontend && npm ci && npm test && npm run build`. Чтобы увидеть сборку в Docker, вернитесь в корень и выполните `docker compose -f compose.yaml -f compose.mail-test.yaml up --build -d`.

## Как устроен интерфейс

- `#events` открывает каталог. В `App` хранятся фильтры и смещение списка. Справочники загружаются из API, а `eventParams` сериализует дату и цену. `FeaturedEvents` прокручивает ряд ближайших карточек. `Poster` переиспользуется в каталоге и подборке.
- `#chat` открывает чат. Кнопки «С семьёй», «С друзьями» и «Бесплатно» отправляют отдельный запрос с `preset`. Ручное сообщение передаёт предыдущий текст в пределах 500 символов. Ответ и выбранные площадки хранятся в состоянии React. Перезагрузка очищает чат и маршрут.
- `#account` открывает профиль. `Account` переключает ввод адреса, ввод кода и состояние входа. `Preferences` читает и сохраняет параметры рассылки. API идентифицирует пользователя по cookie, которая устанавливается сервером.
- `orderedStops` сортирует выбранные события по времени начала. `buildRoute` вызывает внешний сервис с координатами. `Map.jsx` отображает результат, а `mapLinks` строит ссылки из остановок. Для длинного Google-маршрута соседние участки имеют общую точку. Сервисы карт пересчитывают геометрию по своим данным.

## Telegram-бот от входящего сообщения до ответа

1. Сервис `bot` в профиле Compose `telegram` запускает `python -m app.bot`. В `main` клиент Telegram регистрирует `COMMANDS` через `setMyCommands` и запускает одновременно цикл сообщений и рассылку.
2. `poll` забирает сообщения методом `getUpdates` с long polling. Смещение обновляется по `update_id`. Ошибка отдельного сообщения записывается в лог, обработка следующих сообщений продолжается. Сбой самого polling вызывает паузу перед повтором.
3. `handle_message` отделяет команду от аргумента и учитывает суффикс `@имя_бота`. `/random` выбирает одно событие из максимум 200 будущих карточек. `/family` и `/weekend` отправляют готовые шаблоны в FastAPI. Свободный текст идёт в тот же `POST /ai/search`, которым пользуется сайт.
4. `send_results` пытается отправить HTML-виджет в личном чате. `results_widget` экранирует данные, ограничивает подборку пятью карточками и проверяет размер HTML и сжатого содержимого. При отказе `sendWidget` бот отправляет текст с датой, ценой и ссылкой. `/start` дополнительно отправляет меню текстом.
5. Для привязки пользователь входит на сайте по почте и запрашивает ссылку в профиле. `POST /preferences/telegram` сохраняет хеш одноразового токена. `/start <токен>` вызывает `connect_chat`, который проверяет срок действия, привязывает ID личного чата и удаляет хеш токена. Эта ветка доступна только в личных чатах. У одного Telegram-чата может быть одна привязка.
6. `weekly_loop` раз в пять минут вызывает `weekly_round`. В четверг после 18:00 в часовом поясе `Asia/Yekaterinburg` он выбирает активные подписки, ищет до пяти событий на семь дней и сохраняет ISO-неделю после успешной отправки. Отметка и блокировка строки защищают от обычной повторной отправки. Сбой между подтверждением Telegram и фиксацией транзакции может привести к повтору.

### Локальная проверка бота

1. Создайте тестового бота в BotFather, запишите токен в корневой `.env` и запустите профиль `telegram`. Для одного токена должен работать один процесс long polling.
2. Откройте личный чат и отправьте `/start`, затем `/random`, `/family` и `/weekend`. Сверьте меню и карточки. Для проверки привязки пройдите вход через Mailpit, сформируйте ссылку в профиле, откройте её в Telegram и нажмите Start.
3. При проблеме посмотрите `docker compose logs --tail=100 bot api`. Проверьте токен через `getMe` и убедитесь, что у бота нет активного webhook или другого процесса polling. Проверьте `POST /ai/search` отдельно, чтобы отличить проблему каталога или Ollama от проблемы доставки Telegram.
4. Для новой команды обновите `COMMANDS`, её обработку и сценарий проверки. Для еженедельной рассылки меняйте расписание в `digest.py`, а параметры подписки — в `community.py` и `Preferences.jsx`.

## Как вносить изменения

| Задача | Последовательность |
| --- | --- |
| Добавить фильтр каталога | Уточнить его тип и поведение при пустом значении. Добавить поле в `EventFilter`, передать его через `events.py`, реализовать параметризованное условие в `crud.py`, подключить элемент формы и сериализацию. Проверить, например, что значение 0 не теряется. |
| Добавить шаблон подборки | Согласовать ключ между фронтендом и `QueryIn.preset`. Определить диапазон дат и обязательные ограничения в `ai_search`. Проверить обычный, пустой и граничный результат и отдельно проверить ответ при недоступной модели. |
| Изменить импорт | Начать с `backend/run_parcer.py`. Проверить даты и часовой пояс, ID события, цены, координаты и сохранение сырого JSON. Выполнить повторный импорт и убедиться, что записи обновились без дублей. |
| Добавить поле в БД | Определить, как заполняется поле для старых строк. Обновить SQLAlchemy-модель, подготовить миграцию существующей базы и проверить на копии данных. Затем при необходимости обновить API-схему и интерфейс. |
| Изменить API | Сверить статус, тело ответа и обработку ошибок в клиентах. Проверить прямой вызов FastAPI и путь через Nginx. Обновить таблицу API и пример вызова в этой документации. |

## Эксплуатация и восстановление

Логи отдельных сервисов доступны командой `docker compose logs --tail=100 <сервис>`. Нормальный сигнал для API — успешный `GET /health`. Нормальный сигнал для каталога — карточки из `GET /events/` и завершившийся импорт в логах. Успешный `/health` подтверждает доступность PostgreSQL, а доступность Ollama, SMTP, источника и Telegram проверяется отдельно.

Для резервной копии используйте `docker compose exec -T db pg_dump -U afisha -d afisha -Fc > afisha.dump`. Перед восстановлением проверьте архив командой `pg_restore --list`. Разверните отдельную базу, восстановите туда копию и проверьте количество событий, выдачу API и вход. В дампе есть данные пользователей, храните его с ограниченным доступом.

В CI сначала откройте упавший шаг сборки или интеграции. При сбое публикации проверьте права на GHCR, при сбое развёртывания — доступность раннера, файл окружения и логи Compose на сервере. Для отката используйте известные рабочие теги образов и совместимую схему базы. Перед откатом со сменой схемы проверьте совместимость на резервной копии.

После изменения проверьте нужный сценарий через браузер или Telegram, прогоните относящиеся к нему тесты, затем обновите документацию. Исходник этой страницы хранится в `docs/confluence.md` в репозитории.
