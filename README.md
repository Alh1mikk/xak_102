# Афиша культуры Башкортостана

```sh
docker compose up --build -d
docker compose logs -f importer
```

Афиша доступна на http://127.0.0.1:8080. API и Swagger доступны на http://localhost:8000/docs. PostgreSQL хранит данные в томе Compose. Импортёр загружает «Бюро Культуры» при старте и повторяет успешный импорт через 24 часа. После ошибки он повторяет попытку через пять минут. Последние успешно импортированные карточки остаются в PostgreSQL. Для разового импорта можно выполнить `docker compose run --rm importer python run_parcer.py` после запуска API.

## API

- `GET /events/` — опубликованные события, фильтры по городу, категории, дате, минимальной цене билета, возрастной маркировке и названию. Для будущих событий передайте `date_from`.
- `GET /events/cities`, `GET /events/categories` — справочники для фильтров.
- `POST /ai/search` принимает JSON `{"text":"куда пойти в субботу с ребёнком до 1000 рублей"}`. При отсутствии возраста ребёнка поиск использует маркировку до 6+ включительно. Даты интерпретируются по времени Башкортостана (UTC+5).
- `POST /sources/` — регистрация источника через заголовок `X-Admin-Token` при заданном `SOURCE_ADMIN_TOKEN`. Подключение импорта нового источника требует отдельного адаптера.

## Telegram и локальная модель

Скопируйте `.env.example` в `.env`, заполните `TELEGRAM_BOT_TOKEN` и выполните `docker compose --profile telegram up --build -d`. Бот использует long polling и обращается к тому же поиску, что и REST API.

Compose запускает Ollama внутри проекта и загружает Qwen2.5 7B при первом старте. Веса хранятся в томе `ollama_models`. Первый запуск API ожидает загрузки модели.

Ollama извлекает фильтры из запроса. PostgreSQL выбирает до 12 ближайших карточек по этим фильтрам. Модель получает запрос и найденные карточки, затем возвращает порядок релевантности карточек. API отдаёт сами карточки из базы, объяснение применённых фильтров и ссылки на источник. Поля `model_used` и `model_ranked` показывают участие модели на двух этапах. При недоступности модели работают обычные фильтры и хронологическая выдача.


## Данные

Импорт хранит ближайший сеанс из источника, ссылку и время последнего появления записи. Повторный импорт обновляет карточки по внешнему ID. При совпадении названия, времени, города и адреса сохраняется одна карточка с несколькими ссылками. Покрытие ограничено данными одного поставщика. Для расширения на районы подходят выгрузка учреждений через PRO.Культура.РФ и календарь «Культурного мира Башкортостана».

Веб-интерфейс на React и Tailwind работает через Nginx. Маршруты `/api/*` проксируются в FastAPI, поэтому веб-сервису не требуется отдельная настройка CORS.

## Тесты и доставка

При сборке образов автоматически запускаются модульные тесты Python и Node. Полный прогон с отдельной PostgreSQL, тестовыми событиями и Nginx:

```sh
docker compose -f compose.test.yaml -p afisha-test up --build --abort-on-container-exit --exit-code-from integration
docker compose -f compose.test.yaml -p afisha-test down -v
```

GitHub Actions прогоняет тесты на pull request и push в main. После успешных тестов на main публикует образы веб-сервиса и бэкенда в GHCR с тегом коммита. Автодеплой запускается при `AFISHA_DEPLOY=true` после регистрации Linux self-hosted runner с меткой `afisha` на целевом сервере. Задайте `AFISHA_ENV_FILE` как абсолютный путь к серверному env-файлу. Compose-проект `afisha-prod` хранит PostgreSQL и модель в постоянных томах. По умолчанию веб-порт привязан к localhost. Для публичного доступа настройте серверный HTTPS-прокси.


## Вход и карта

Веб-вход использует почту. Каталог, чат и карта доступны без входа.

Карта на Leaflet показывает ближайшие события, для которых источник передал координаты площадки. Подложка OpenStreetMap используется без API-ключа с атрибуцией. Условия сервиса тайлов: https://operations.osmfoundation.org/policies/tiles/

## Граница региона и маршруты

Каталог публикует только карточки с координатами площадки внутри Башкортостана. Геометрия границы взята из отношения [OpenStreetMap 77677](https://www.openstreetmap.org/relation/77677), © OpenStreetMap contributors, ODbL. Карточки с отсутствующими или противоречащими границе координатами сохраняются для повторной проверки при следующем импорте.

Из карточек ИИ-подборки можно составить пеший маршрут. Площадки идут по времени начала событий, а маршрут по улицам рассчитывает [FOSSGIS / OSRM](https://routing.openstreetmap.de/). Время просмотра мероприятий в длительность прогулки не включается.

## Вход по почте

В профиле пользователь запрашивает одноразовый код. Настройка SMTP и сессий описана в [документации для Confluence](docs/confluence.md#вход-по-почте). Для бота достаточно `TELEGRAM_BOT_TOKEN` и профиля Compose `telegram`.

### SMTP Gmail или Яндекс Почты

В корневом `.env` задайте `SMTP_HOST=smtp.gmail.com` или `SMTP_HOST=smtp.yandex.ru`, `SMTP_PORT=465` и `SMTP_IMPLICIT_TLS=true`. В `SMTP_USERNAME` и `SMTP_FROM` укажите полный адрес отправителя, в `SMTP_PASSWORD` — пароль приложения. Для `EMAIL_CODE_SECRET` сгенерируйте случайное значение командой `openssl rand -hex 32`.

Переключение на реальный SMTP: `docker compose --profile telegram up -d --remove-orphans`. Для локальной проверки с Mailpit: `docker compose -f compose.yaml -f compose.mail-test.yaml --profile telegram up -d`. Письма в локальном режиме доступны на http://127.0.0.1:8025.

В личных чатах бот отправляет подборки через Telegram `sendWidget`. Если Telegram отклоняет виджет, бот отправляет текстовую карточку.
